# lib/multimod

Cyclic convolution modulo an NTT prime chosen at run time, for products modulo several primes
joined by the CRT. API and usage: the headers of `transform.hpp` (`Transform`, any sizes),
`product.hpp` (`Product`, factors of at most half the transform, faster), `lazy_product.hpp` and
`wide_product.hpp` (its two kernel sets). Tests: `test.cpp`. Timing: `bench.cpp`. Kernels:
`kernels.hpp`, `lazy_kernels.hpp` and `wide_kernels.hpp`, generated by `gen_kernels.py`,
`gen_lazy_kernels.py` and `gen_wide_kernels.py` (do not edit).

## Design

- lib/ntt's transform (recursion, tables, kernels; `lib/ntt/notes.md`) with p a variable.
  `gen_kernels.py` runs lib/ntt's generator and rewrites 6 lines: P, 2P and -1/P mod 2^32 become
  globals that `Modulus::select()` sets before each prime. The instructions are the same.
- Lengths 2^6..2^20; a prime needs p < 2^30 and 2^17 | p - 1. Twiddle tables are rebuilt per
  prime (2^lg / 16 entries each way, AVX2).
- First level (sparse: count <= 2^lg / 2):
  - lg even >= 8, both inputs sparse: one radix-8 pass reads the input, reduces it and writes
    the first radix-4 group of both halves.
  - lg odd: radix 4. A sparse input is reduced and transformed in one pass.
  - Otherwise: reduce into the array, then a radix-2 level (a copy when sparse).
  The scale (and the caller's factor) is fused into the last inverse level.
- Inputs: `Padded` (words < 2p, zero up to half the length: plain loads), `Bounded` (words
  < 2p, masked loads at the end, nothing read past the count), `Wide` (64-bit words,
  hi (2^32 mod p) + lo, for p > 2^29). `detail::Narrow<Input>` turns 8 words into canonical
  residues.
- `multiply` takes the inputs by value, and the first-level passes build `Narrow` from the input
  and the `Modulus` inside the function. `Vec` is `may_alias`, so state behind a reference is
  reloaded after every vector store; by value it stays in registers and shares p and 2p with
  the pass.

## Product

`Product<K>` is lib/ntt's `ntt::Product` (`lib/ntt/notes.md`, "Product") on lib/multimod's tables
and recursion, for factors of at most half the transform, 9 <= lg <= 20. `Subtrees<K>` runs two
bottom groups per kernel; the top levels are fused as in ntt::Product. The kernel set K supplies the
kernels, the first levels (in its order of a and b, which sets the in-place rules) and the last
level for odd lg:

| Set | Primes | Factors | Kernels |
|---|---|---|---|
| `LazyProduct` | p < 2^28 | uint32 words < 4p, used raw | `lazy_kernels.hpp`: values up to 16p between reductions (forward < 8p, inverse < 4p) |
| `WideProduct` | 2^29 < p < 2^30 | 64-bit words (`Wide`) | `kernels.hpp` for the transform; ntt::Product's bottom stage and inverse top modulo p, and `forward_radix8_wide` (`wide_kernels.hpp`) |

The kernels are named in K by reference (`static constexpr auto& forward = ...`); GCC calls them
directly (round 3 log).

## Users

| Problem | Uses | Primes |
|---|---|---|
| convolution_mod_1000000007 | LazyProduct | 3 |
| convolution_mod_2_64 | WideProduct; Transform (Wide) when a factor fills more than half | 5 |
| multivariate_convolution_cyclic | LazyProduct | 3 |

`Padded` and `Bounded` (Transform's inputs) have no user since convolution_mod_1000000007 and
multivariate_convolution_cyclic moved to LazyProduct; the tests keep them.

Not moved: `multivariate_convolution/transform.hpp` is a different transform (P = 998244353,
forward and inverse as separate steps), not a copy.
